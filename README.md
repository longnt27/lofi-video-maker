# Lo-fi generator v3.2: clean progress, real logs, reliable LaMa provider

The v3.2 update addresses the repeated `Context leak detected, CoreAnalytics returned false`
messages on macOS. This warning is generated by the native CoreML execution path;
it is not a frame-progress indicator and does **not** prove that processing has
stopped. LaMa may genuinely be slow: at 30 fps, a 10-second source requires
about 300 model inferences.

**What changed**

- The terminal shows numbered stages, meaningful progress, and the location of
  a timestamped detailed log. FFmpeg, NCNN, ONNXRuntime, and native CoreML output
  go to the log, not your terminal.
- LaMa runs as a child process. Progress is reported at frame milestones and
  liveness warnings appear when no frame advances for more than 45 seconds.
- On macOS, **CPU is the default LaMa provider** to avoid CoreML's repetitive
  warnings and partial graph execution. It may be slower or faster depending
  on the model and machine. Try `--lama-provider coreml` only if you want to
  compare performance; `--lama-provider auto` restores the previous preference.
- The log records commands, diagnostics, and errors. External-process failures
  show a brief diagnostic and the location of the full log.
- The cached short clip is re-used after successful preparation. Changing the
  LaMa provider intentionally changes the cache key.

## Quick command for your current project

Use the `--watermark-box` coordinates printed during your previous selection,
so you don't need the GUI again. The coordinates in your screenshot were
`1698,865,81,70`; verify they match the current source video.

```bash
python lofi_maker.py \
  --video data/video.mp4 \
  --music ./data/musics \
  --output lofi_4k.mp4 \
  --watermark-box 1698,865,81,70 \
  --lama-provider cpu \
  --upscale 2 \
  --cache-dir ./cache \
  --fade 3 \
  --codec hevc
```

For an explicit log file path, add `--log-file ./lofi-run.log`.
If omitted, logs are saved in `./cache/logs/lofi_YYYYMMDD_HHMMSS_PID.log`.
Inspect the newest log in a second Terminal window:

```bash
ls -t cache/logs/*.log | head -1
# Then:
tail -f "$(ls -t cache/logs/*.log | head -1)"
```

# Lo-fi video maker v3: reuse your existing NCNN + LaMa + drifting dust

**What's new in v3:** Reuses the Real-ESRGAN installation already present in
another local project. It detects `bin/realesrgan-ncnn-vulkan` and
`bin/models/realesr-animevideov3-x{2,3,4}.{bin,param}`. The script now passes
the model directory using NCNN's `-m` argument. **No NCNN downloads or copying
of its large models are needed.**

```text
projects/
  other-project/
    bin/
      realesrgan-ncnn-vulkan
      models/
        realesr-animevideov3-x2.bin
        realesr-animevideov3-x2.param
        realesr-animevideov3-x3.bin
        realesr-animevideov3-x3.param
        realesr-animevideov3-x4.bin
        realesr-animevideov3-x4.param
  lofi_pipeline/
    lofi_maker.py
    video_preprocess.py
```

If the projects are siblings, the installation is discovered automatically.
You can also run the script **from inside** the other project, or point it at
an arbitrary location with `--realesrgan-root /path/to/other-project`.

A command-line pipeline for macOS (especially Apple Silicon), Linux, or Windows with FFmpeg installed. It converts one short, seamless looping video and a directory of music into a lo-fi MP4 with opening/closing fades, song crossfades, and alternating one-minute clean/dust sections.

**Optional preprocessing** is based on the supplied notebooks:

| Notebook | Integrated feature | Mac M4 adaptation |
|---|---|---|
| `Watermark.ipynb` | LaMa (`lama_fp32.onnx`) removes a marked rectangular watermark region frame by frame | ONNX Runtime CPU by default on macOS, with optional CoreML; no NVIDIA CUDA requirement. |
| `EnhanceVideoQuality.ipynb` | `realesr-animevideov3` AI upscales the original short clip by 2×/3×/4× | Reuses the **existing** `bin/realesrgan-ncnn-vulkan` and `bin/models/` from the other project, instead of the notebook's NVIDIA CUDA PyTorch script. |
| `EnhanceVideoQuality.ipynb` | Optional FFmpeg `nlmeans` denoising and `minterpolate` motion interpolation | Both optional (off by default), because they are slow and usually unnecessary for a lo-fi animation. |

**Important:** This is not a verbatim execution of the two Colab notebooks. The AI algorithms are preserved where specified, but their Colab GUI, NVENC encoder, and 96-FPS default are not. The final encoder is H.264/HEVC using Mac VideoToolbox when available (8-bit 4:2:0 by default).

## Pipeline design

```
source.mp4 (e.g. a 10s 1080p loop)
  |
  +--> [optional LaMa watermark inpainting]
  |      * one rectangle, coordinates in ORIGINAL source pixels
  |
  +--> [optional FFmpeg denoise]
  |
  +--> [optional 2x Real-ESRGAN anime-video AI upscale]
  |      * e.g. 1920x1080 -> 3840x2160
  |
  +--> prepared short clip (cached, processed ONCE)
            |
            +--> clean 60-second clip
            +--> 10 unique 60-second drifting dust clips
            |
            +--> 60s CLEAN / 60s DUST1 / CLEAN / DUST2 ... DUST10
            |      (then repeat until the soundtrack is finished)
            |
folder of MP3/M4A/FLAC/... --> combine songs + 2-second crossfades
            |
            +--> final MP4 with GLOBAL picture + music fades at BOTH ends
```

Each dust section has its own particle-only fade-in/out. The underlying scene never fades to black between minute sections.

## 1. Install requirements

Install FFmpeg:

```bash
brew install ffmpeg
```

Install the Python dependencies *only if you want LaMa watermark inpainting*. A virtual environment is recommended:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-watermark.txt
```

On Apple Silicon, use ordinary `onnxruntime`, **not** `onnxruntime-gpu` (the original notebook was for an NVIDIA T4). To see whether ONNX Runtime can use the CoreML execution provider on your Mac:

```bash
python3 -c 'import onnxruntime as ort; print(ort.get_available_providers())'
```

If `CoreMLExecutionProvider` is missing or an op can't run on it, the script can use the CPU provider. CoreML availability does **not** guarantee every LaMa operator runs on the Neural Engine.

### Reuse the existing Real-ESRGAN installation

**Nothing to download.** Your other agent already placed the macOS NCNN
executable and the x2/x3/x4 anime-video weights in a project's `bin/` folder.
Verify that the new pipeline can see them:

```bash
python3 lofi_maker.py --check-upscaler
```

If the other project is elsewhere on your Mac:

```bash
python3 lofi_maker.py \
  --check-upscaler \
  --realesrgan-root "$HOME/path/to/other-project"
```

Use the **real path** to that project rather than literally copying the example.
For a permanent setting, instead of repeating the option:

```bash
export LOFI_REALESRGAN_ROOT="$HOME/path/to/other-project"
python3 lofi_maker.py --check-upscaler
```

The discovery order is: explicit binary / environment override; specified
project root; current or script directory's `bin/`; executable on `PATH`;
one-level sibling-project search. The model files are found from the binary's
adjacent `models/` directory first. You can override them with
`--realesrgan-model-dir`. `LOFI_REALESRGAN_BIN` and
`LOFI_REALESRGAN_MODELS` are also supported.

**Important:** `--check-upscaler` checks executable permissions and matching
model files; it does not prove that the old 2022 macOS Vulkan binary can run
on your M4. Try `--prepare-only` on a short source to test actual inference.
The pipeline fails explicitly if NCNN doesn't work rather than silently
substituting a lower-quality upscale.

The NCNN executable/models remain in your existing project and are **not**
bundled here. The LaMa `.onnx` model is a different dependency and will still
download into the cache the first time you actually request watermark removal
(unless you pass `--lama-model` with a local ONNX file).

## 2. Choose a watermark rectangle

Use the GUI selector on a Mac with a desktop session:

```bash
python3 lofi_maker.py \
  --video "my_10sec_loop.mp4" \
  --pick-watermark \
  --prepare-only cleaned_preview.mp4 \
  --cache-dir ./lofi-cache
```

Drag a rectangle around the watermark, then press Enter. The script prints the corresponding `--watermark-box x,y,width,height` value, e.g. `--watermark-box 1750,900,130,90` for a 1920×1080 source. Use those coordinates for repeated runs without opening the GUI.

**Only use watermark removal on media you're authorized to modify.** Removal does not confer rights to an animation or its soundtrack.

## 3. Test the SHORT video before making an hour-long mix

Example: remove an example watermark at `(1700,900)` of size `120x70` and upscale a **1080p** short clip to 4K with AI:

```bash
python3 lofi_maker.py \
  --video "my_10sec_loop.mp4" \
  --watermark-box 1700,900,120,70 \
  --upscale 2 \
  --upscale-engine ai \
  --cache-dir ./lofi-cache \
  --prepare-only "prepared_4k.mp4"
```

Replace the example box with the actual coordinates from your video. The output is a short cleaned/upscaled video you can inspect before rendering the full mix. Run the command without `--watermark-box` if the source has no watermark.

If you just need a portable upscale that requires no AI binary:

```bash
python3 lofi_maker.py --video my_10sec_loop.mp4 \
  --upscale 2 --upscale-engine lanczos \
  --prepare-only prepared_4k.mp4 --cache-dir ./lofi-cache
```

## 4. Generate the finished lo-fi video

```bash
python3 lofi_maker.py \
  --video "my_10sec_loop.mp4" \
  --music "./songs" \
  --output "lofi_4k.mp4" \
  --watermark-box 1700,900,120,70 \
  --upscale 2 \
  --upscale-engine ai \
  --fps 30 \
  --fade 3 \
  --crossfade 2 \
  --dust-variants 10 \
  --section-seconds 60 \
  --dust-fade 5 \
  --cache-dir "./lofi-cache" \
  --codec hevc
```

**Soundtrack:** All supported songs in the folder are combined in natural filename order with 2-second crossfades (MP3, M4A, FLAC, WAV, AAC, OGG, Opus, AIFF). Use `--shuffle` for randomized order. The video lasts as long as this combined soundtrack, not a fixed hour.

**Video:** First 60 seconds clean, next 60 seconds dust variation 1, then clean, dust variation 2, etc. After variation 10, repeats. The *whole* video and audio fade at the very beginning and end (not every minute). The short source must loop seamlessly for a perfect background animation.

## 5. Rendering options

| Option | Default | Meaning |
|---|---|---|
| `--watermark-box x,y,w,h` | off | Run LaMa AI on this rectangle using ORIGINAL video pixel coordinates |
| `--pick-watermark` | off | Interactively select the region using OpenCV GUI |
| `--lama-model FILE` | downloaded | Use an existing ONNX model, no network download |
| `--watermark-feather 3` | 3px | Blend the AI patch edges |
| `--watermark-grain 0` | 0 | Add film grain only to the repaired patch |
| `--upscale 2` | 1 (off) | Upscale short source by factor 2/3/4 |
| `--upscale-engine ai` | ai | Real-ESRGAN NCNN engine; requires binary and models |
| `--upscale-engine lanczos` | - | Standard FFmpeg resize; not neural |
| `--upscale-model` | realesr-animevideov3 | Model used by the uploaded enhancement notebook |
| `--check-upscaler` | off | Find the existing NCNN binary + model files and exit |
| `--realesrgan-root` | auto | Root of the *other* project holding `bin/` and `bin/models/` |
| `--realesrgan-bin` | auto | Exact executable path if auto-detection is insufficient |
| `--realesrgan-model-dir` | auto | Exact model directory if not beside executable |
| `--upscale-tile 128` | 128 | AI tile dimension; smaller may reduce memory requirements |
| `--denoise` | off | FFmpeg nlmeans from the enhancement notebook |
| `--motion-interpolation` | off | FFmpeg motion-compensated interpolation to `--fps` |
| `--fps` | 30 | Output 24/25/30/50/60 fps (96 fps NOT default) |
| `--codec hevc` | hevc | Prefer HEVC/H.265; `h264` for broader compatibility |
| `--fade` | 3 sec | Global opening and ending fade for the finished video/music |
| `--crossfade` | 2 sec | Crossfade between songs |
| `--dust-variants` | 10 | Distinct dust patterns |
| `--dust-count` | 65 | Dust particles in each dust frame |
| `--dust-fade` | 5 sec | Dust fades at each dust segment's beginning/end |
| `--dust-fps` | 15 | Particle motion sampling rate (video remains at `--fps`) |
| `--no-dust` | off | Loop clean prepared source only |
| `--preview 125` | off | Produce first 125 seconds (allows viewing first dust phase) |
| `--prepare-only output.mp4` | off | Export just the cleaned/upscaled short source, without music |
| `--cache-dir ./lofi-cache` | off | Persistent cache of AI-enhanced short video and minute clips |

**Performance:** AI cleanup/upscaling happens once per source/configuration. A first full export still has to encode the 10 dust variations at final resolution, then copy the pre-encoded minute sections. Persistent caching keeps subsequent mixes with the same source faster. A higher resolution, more dust, optional `nlmeans`, and motion interpolation all increase processing time.

## Limitations and QA

- An animation with a moving/transparent watermark may need a larger mask or a different tracking method. The integrated LaMa operation is based on **one fixed rectangle** across frames, as in the uploaded notebook.
- LaMa changes pixels inside the selected region; inspect the loop for flickering or soft patches, especially near moving details.
- The Real-ESRGAN implementation is the model family from the notebook, but **NCNN can produce slightly different results from PyTorch** (e.g. tiling behavior), as documented upstream.
- 2× upscale means **1080p -> 4K**, not automatically any other source -> 4K. An already-4K input at 2× becomes 8K and may be excessive on 16 GB RAM.
- Raw extracted PNG frames can need substantial temporary disk space. Temporary data is deleted after preparation completes.
- Local smoke tests cover music merging, 2× Lanczos scaling, dust alternation, whole-video fades, cached short clips, mock LaMa inference, auto-detection of another project's `bin/models/`, explicit `-m`, and cache invalidation when weights change. **Actual LaMa inference, real Real-ESRGAN output, and Mac M4 hardware performance were not benchmarked here.**
